# Coinly UI 设计规范

Coinly 是本地优先的个人财务工具。界面应轻盈、亲和、可快速扫描，不使用营销式大标题、装饰性卡片堆叠或与任务无关的视觉元素。

## 设计原则

1. 高频任务优先：记账、查看明细和本月收支始终比设置与管理更容易到达。
2. 原币种表达：不同币种不合并为单一总额，金额始终显示币种并使用等宽数字。
3. 渐进呈现：恢复、筛选、标签、备注等低频内容按需展开。
4. 明确反馈：保存、同步、导入和 AI 操作必须显示进行中、成功或可行动的错误信息。
5. 本地可信：界面不暗示服务端托管；同步与 AI 能力需要明确配置后才可用。

## 视觉令牌

令牌集中定义在 `src/styles.css`，组件不得硬编码主题颜色。

- `--color-accent`：清爽青绿色，用于主按钮、当前导航、焦点和选中态。
- `--color-on-accent`：强调色表面的专用深色前景；浅色与深色主题都不得直接复用正文色。
- 支出和负向财务趋势使用语义危险色，不额外维护装饰性色。
- `--color-success`：收入、正净额和成功状态；不得用品牌强调色替代，以保持业务语义稳定。
- `--color-error`：验证失败、同步失败和危险系统状态。
- `--color-surface`：主要内容表面；`--color-surface-muted` 用于筛选区、次级行和轻量分组。
- `--color-border`：结构边界。优先使用分隔线，不用阴影制造多层卡片。

常规圆角使用 3px、4px、6px，胶囊形状只用于状态、币种和标签。页面优先加载 Inter，并提供系统字体回退。

## 信息层级

- 页面标题：每页一个 `h1`，与主操作同一行；手机允许操作换行。
- 区块标题：使用 `h2`，紧邻内容，不额外套装饰卡片。
- 金额：主摘要使用 24px，列表金额使用 14–16px，统一 `tabular-nums`。
- 辅助信息：日期、币种、数量和说明使用次级文字色，不能代替字段标签。
- 文案：按钮使用具体动作，如“保存交易”“生成账单”，避免“继续”“确定”等模糊表述。

## 导航

桌面侧栏按以下顺序分组：

- 日常：概览、记账、明细。
- 洞察：统计、助手。
- 规划：预算、订阅。
- 管理：账户、分类标签、设置。

手机底栏固定为概览、明细、记账、统计、助手、更多。低频页面位于“更多”抽屉；信用卡账期是明细的子页签，不进入全局导航。

所有路由使用真实链接，普通点击由 History API 接管，同时保留新标签页、复制链接、前进和后退能力。

## 页面模板

### 创建与解锁

口令和主按钮直接显示。完整账本、同步配置、扫码和二维码图片位于“从备份恢复”展开区。错误紧邻表单并进入辅助技术通知区域。

### 概览

首屏依次为页面标题与快速记账、本月多币种摘要、最近交易、账户流动、预算和订阅。首页列表最多展示 6 项，完整数据在对应页面查看。

### 记账

字段顺序为交易类型、金额、币种、账户、分类/关联账户、日期。标签与备注默认折叠；主提交按钮在手机上保持可触达。

### 明细与账期

搜索常驻，高级筛选按需展开。筛选和分页写入 URL。桌面使用语义表格，手机使用交易列表；批量危险操作只在存在选中项时可用。

### 统计与 AI

收入使用成功色，支出使用危险语义色。图表必须同时提供文字金额。AI 默认根据输入自动路由问账、记一笔、分析和补全任务；输入 `@` 可显式选择工具。写入账本前必须由用户确认候选项。

### 管理与设置

管理页使用列表和新建抽屉，编辑与删除为次级图标操作。账户、预算、分类标签、订阅和 AI 提供商都从对应一级页面管理，不在设置中重复入口。设置页只保留同步、币种、数据与安全；主题由全局导航控制。

## 响应式与触控

- 手机：390px 起，底栏与抽屉考虑安全区，交互控件最小高度 44px。
- 平板：768px 起切换桌面侧栏；双列表或表单可使用两列。
- 桌面：1440px 下内容宽度不超过 1280px，数据表允许自身横向滚动。
- 页面禁止整体横向滚动；长名称必须截断或换行，金额不得挤压主要标签。

## 可访问性

- 使用 `button` 执行动作、`a` 导航、`form` 提交、`table` 展示表格数据。
- 图标按钮必须提供可读名称和 `title`，装饰图标设置 `aria-hidden="true"`。
- 所有字段有可点击标签、稳定 `name`、合适的 `type`、`inputMode` 和 `autocomplete`。
- 键盘焦点使用 `:focus-visible`；弹窗关闭后恢复焦点，提交失败聚焦第一个错误字段。
- 动效仅使用透明度和变换，并遵守 `prefers-reduced-motion`。
- 不禁用缩放；在 200% 缩放下仍需完成主要流程。

## 发布验收

1. 在 390×844、768×1024、1440×900 检查创建/解锁及全部路由。
2. 覆盖空账本、典型数据、长名称、大金额、多币种和 50 条以上明细。
3. 检查浅色、深色、系统主题及缩减动效。
4. 仅用键盘完成创建、记账、筛选、编辑、删除确认和设置导航。
5. 回归导入导出、二维码、同步冲突、账期结算与 AI 候选确认。
6. 运行 `pnpm test`、`pnpm lint` 和 `pnpm build`。
